# Cross-repo contract artifacts

Machine-readable files that another repository **reads**. Not documentation, not
fixtures: the frontend imports these, so a change here is a change over there.

Everything in this directory is generated from Go constants and checked in. Edit
the constants, run the target, commit both.

| File | Generated by | Read by |
|---|---|---|
| `match-timings.json` | `make contract` | the frontend's AFK-threshold tests |

## Why this exists

The AFK thresholds were the case that argued for it. `AfkTrailingMs = 15_000`
was asserted by **no Go test at all** — every test injects its own value through
`WithAfkKick`, so the production constant was exercised by nothing and could
have been retyped without a single failure. Meanwhile the frontend carried its
own `12_000` as a literal in a store and a second copy in a test.

Two numbers in a fixed relationship, neither pinned, both green whatever the
other did. `docs/MATCH.md` documented them as a pair, but documentation is not a
test.

## The rule for consumers

The client's thresholds must sit **strictly inside** the server's. A client that
gives up *later* than the server shows a player still racing after the server has
already `dnf`'d them; a client that gives up *earlier* is merely conservative,
which is the safe direction. That is the assertion a consumer should make against
these numbers — not equality, which would force both repos to move in lockstep
for no benefit.

## Changing a value

1. Change the Go constant.
2. `go test ./internal/ws/ -run TestMatchTiming` fails — it asserts the values
   themselves. That failure is the point: read it, decide the change is real.
3. `make contract` regenerates the artifact.
4. Commit the constant, the test and the artifact together, and tell the
   frontend: its own thresholds may now be outside the server's.
